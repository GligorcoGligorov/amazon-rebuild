## What was wrong

My bug, from M5. The merge claimed the guest cart **in place** — setting `user_id` while leaving its `session_token` — so the cookie in your browser still resolved to a cart that now belonged to a user. Reads went by session token alone, so a signed-out visitor saw it, and the next sign-up claimed it again.

Worth naming plainly: on a shared or borrowed computer this leaks one person's cart to another. It's a privacy bug, not just a tidiness one.

## The fix

Cart ownership is now exclusive: `session_token` set and `user_id` null (guest), or `user_id` set and `session_token` null (user). **A `CHECK` constraint refuses anything else** — the application code alone had already failed to hold this line, so the database enforces it now. I confirmed it rejects the bad row shape outright.
